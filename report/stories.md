# 变更影响范围分析 (Impact Scope Analysis)

基于 `约定式提交 (Conventional Commits)` 规范，针对“算子添加”模块在底层 InfiniCore 库的支持，其影响范围分析如下：
- `feat(kernel)`: 新增基于 CUDA 11.x + cuDNN 8.x 的 `.cu` GPU Kernel 高性能实现。
- `build(cmake)`: 扩展 CMakeLists.txt，新增多硬件后端（BACKEND）的跨平台编译选项预留。
- `test(benchmark)`: 新增底层 Kernel 的性能基准测试脚本及性能评估报告导出。
- `docs(kernel)`: 新增底层算子添加相关的 README.md 说明文档。

---

# User Stories

## Story 1: 任务一 - 算子接口定义与底层注册

**1. 明确的业务价值与验收标准 (Definition of Done)**
- **业务价值**：为上层编译器提供清晰、一致的底层算子 C-API 契约，支撑 CPU 与 NVidia 路径的底层注册寻址。
- **验收标准 (DoD)**：
  - 完成算子参数（输入/输出/属性）的底层 API 头文件声明。
  - 配合上层的算子注册表，完成底层执行器的映射挂载。
  - 所有代码须通过 `clang-format` 规范检查（Google 风格）。
  - 单元测试行覆盖率 ≥ 90 %。
  - 产出对应的任务 `README.md`，包含编译命令、运行示例、已知限制。

**2. 前置依赖、输入输出及接口变动清单**
- **前置依赖**：明确上层 IR 层所需透传的所有算子属性规范。
- **提交物**：
  - ① 底层算子的 API 声明头文件与对应实现壳。
  - ② 注册代码补充。

**3. 测试策略与回归范围**
- **测试策略**：C++ 原生层面的 API 参数校验与异常状态拦截测试。
- **回归范围**：底层算子调度器与统一 C-API 导出表。

**4. 预计工作量与优先级**
- **预计工作量**：1 人日
- **优先级**：高 (P0)

## Story 2: 任务二 - NVidia RTX2060 后端 kernel 实现

**1. 明确的业务价值与验收标准 (Definition of Done)**
- **业务价值**：针对目标硬件（NVidia RTX2060）提供高性能、高精度的算子物理执行落地，确保算力被充分利用。
- **验收标准 (DoD)**：
  - 基于 `CUDA 11.x` + `cuDNN 8.x` 实现对应 GPU kernel，完全支持 `FP32` 与 `FP16` 两种精度。
  - 物理指标要求：实现内存访问对齐、合并读写（Coalesced Memory Access），Warp 级别并行度必须 ≥ 32。
  - 精度误差要求：计算误差 ‖output_ref – output‖∞ 须满足 ≤ 1e-4（FP32）及 ≤ 1e-2（FP16）。
  - 性能基线要求：在 RTX2060 上，输入典型形状 (N=32, C=256, H=128, W=128) 的执行时间 ≤ 原生实现的 110%。
  - 所有新增 `.cu` 代码通过 `clang-format`（Google 风格）检查，文档齐备。

**2. 前置依赖、输入输出及接口变动清单**
- **前置依赖**：本地已配置 CUDA 11.8 环境及 Nsight Systems (nsys) 性能分析工具。
- **提交物**：
  - ① 核心计算的 `.cu` 源文件。
  - ② 性能基准测试（Benchmark）脚本。
  - ③ nsys 导出的性能报告。

**3. 测试策略与回归范围**
- **测试策略**：
  - **精度比对**：与标准的 CPU 裸量算子实现进行逐元素误差比对。
  - **性能压测**：通过基准脚本重复执行预热与计时，分析内存带宽与计算吞吐（TPS）。
- **回归范围**：底层 CUDA Stream 的上下文管理及工作区（Workspace）内存分配安全性。

**4. 预计工作量与优先级**
- **预计工作量**：4 人日
- **优先级**：最高 (P0)

## Story 3: 任务三 - 单平台冒烟验证与多平台架构预留 (底层扩展层)

**1. 明确的业务价值与验收标准 (Definition of Done)**
- **业务价值**：为未来接入国产算力芯片建立标准的多平台扩展骨架，实现“一次接入，多端编译”。
- **验收标准 (DoD)**：
  - （3.b 多平台架构设计）成功在算子目录下预留对应的硬件子目录 `muxi`、`tianshu`、`moore`。
  - 对应子目录内需创建空实现模板，确保在调用时安全返回 `NotImplementedError`，为后续填充预留桩代码。
  - 构建系统新增 `BACKEND` 枚举值（MUXI/TIANSHU/MOORE），并保证 CMake 可通过 `-DBACKEND=xxx` 参数无缝切换。
  - 提交完整的 `README.md` 与平台扩展规范。

**2. 前置依赖、输入输出及接口变动清单**
- **前置依赖**：对现有 InfiniCore 底层多后端构建目录结构（如 cpu, cuda, bang, kunlun）的理解。
- **提交物**：
  - ① 目录结构图。
  - ② `CMakeLists.txt` 改动 diff 文件。
  - ③ 统一的平台抽象接口头文件。

**3. 测试策略与回归范围**
- **测试策略**：利用带不同 `-DBACKEND=` 参数的 CMake 配置指令进行交叉编译预检，验证是否能正确命中对应的空实现模板且不发生链接阶段报错。
- **回归范围**：现有项目的 CMake 宏定义树与硬件条件编译宏（如 `#ifdef USE_CUDA` 等）。

**4. 预计工作量与优先级**
- **预计工作量**：2 人日
- **优先级**：中 (P1)
