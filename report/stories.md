# 变更影响范围分析 (Impact Scope Analysis)

基于 `约定式提交 (Conventional Commits)` 规范，针对 InfiniTensor 集成需求涉及到的底层库（InfiniCore）支持，本次更新带来的影响范围分析如下：

- `feat(api)`: 审查、确认并暴露目标核心算子（如 Clip, Conv, LayerNorm, UnaryOps 等）的标准 C-API。包括算子描述符构建、工作区（Workspace）大小查询及底层执行函数的导出。
- `fix(kernel)`: 修复在多平台联调验证中可能出现的特定硬件底层执行错误、内存数据排布（Layout）对齐异常或状态码处理等潜在 Bug。
- `test(ops)`: 新增或完善各新增核心算子在独立环境下的边界测试用例（如空张量输入、非连续内存块、零尺寸维度等）。
- `perf(kernel)`: 针对上层框架的调用特征，针对性优化底层计算实现或显存访存开销，提升在特定硬件环境下的 TPS 吞吐或延迟指标。

# User Stories

## Story 1: 底层算子 C-API 接口对齐与确立 (Underlying Operator C-API Alignment)

**1. 明确的业务价值与验收标准 (Definition of Done)**
- **业务价值**：为上层 InfiniTensor 框架提供稳定、一致、高内聚的底层调用契约，确保框架层的算子创建、空间查询与硬件执行的生命周期能安全、无缝地接入。
- **验收标准 (DoD)**：
  - 目标算子（如 `infiniopAdd`, `infiniopClip` 等）的 C 头文件对外接口定义清晰且 ABI 稳定。
  - 算子描述符（`Descriptor`）的内存分配与释放流程严格闭环，避免上层调用引发内存泄漏。
  - API 函数签名能够完整涵盖上层 PyTorch 语义所需的所有关键计算属性与超参。

**2. 前置依赖、输入输出及接口变动清单**
- **前置依赖**：InfiniTensor 前端对于算子属性映射的完整性分析需求。
- **输入输出**：输入为标准化的形状维度数组、张量裸指针以及硬件异步流（Stream）；输出为执行状态返回码（`infini_status_t`）及目标设备显存中的运算结果。
- **接口变动清单**：
  - `include/infiniop/ops/xxx.h`（确认及增补对应的 C-API 函数声明：包含执行与空间查询等）

**3. 测试策略与回归范围**
- **测试策略**：在 InfiniCore C++ 原生测试套件中，绕过框架直接调用底层 C-API。验证返回值在传入非法指针或不合法形状时是否能被准确拦截并返回对应的错误码。
- **回归范围**：已有核心算子的 ABI 兼容性，以及动态链接库的导出符号表，确保框架侧链接不会发生 `undefined reference`。

**4. 预计工作量与优先级**
- **预计工作量**：1 人日
- **优先级**：高 (P0)

## Story 2: 算子工作区与内存复用管理支持 (Workspace Management Support)

**1. 明确的业务价值与验收标准 (Definition of Done)**
- **业务价值**：支持上层框架进行全局精准的内存池复用规划（Memory Planning），减少运行时执行的显存分配开销，避免算子执行 OOM 从而提升端到端推理与训练效率。
- **验收标准 (DoD)**：
  - 对于带有中间缓存需求的核心算子，其 `infiniopGetXXXWorkspaceSize` 接口能依据不同输入规模精确返回字节数。
  - 若不需要临时空间，查询接口必须稳定返回 0 字节，而不断言或宕机。
  - 在计算 API 中传入对应的 Workspace 裸指针时，算子底层内核不会发生超出预报大小的越界读写操作。
  - 计算所需的空间完全独立于算子内部状态，确保在并发执行流（Stream）中的线程安全。

**2. 前置依赖、输入输出及接口变动清单**
- **前置依赖**：各类算子在特定硬件平台（如 Im2Col 之于卷积操作，或 Reduce 归约阶段）对缓存 Buffer 的具体算法实现需求。
- **输入输出**：输入为已装配完成的 `Descriptor`，输出为代表所需字节大小的 `size_t` 结果值。
- **接口变动清单**：
  - 底层各硬件后端（CPU/CUDA/BANG/KUNLUN 等）实现目录下的 `operator.h` 与 `operator.cc`（关于 `getWorkspaceSize` 接口或类似机制的完善）。

**3. 测试策略与回归范围**
- **测试策略**：构造包含极大形状和极小形状（如标量）的用例，测试工作区容量计算是否存在整型溢出漏洞；结合 AddressSanitizer (ASan) 捕获运行期的空间越界行为。
- **回归范围**：InfiniCore 底层公用的设备句柄管理模块（Handle/Context）以及任何涉及跨算子临时空间分配的复用逻辑。

**4. 预计工作量与优先级**
- **预计工作量**：2 人日
- **优先级**：高 (P0)

## Story 3: 多硬件平台底层算子正确性联调与验证 (Multi-Platform Correctness Validation)

**1. 明确的业务价值与验收标准 (Definition of Done)**
- **业务价值**：支撑项目“多硬件平台调用验证”的终极目标，落实“一次编写，异构执行”的编译器核心价值，确保底层算子在英伟达、沐曦、天数、摩尔等芯片上执行结果一致且高可用。
- **验收标准 (DoD)**：
  - 核心算子能在不同平台的交叉编译流水线中通过，无阻断性编译告警或错误。
  - 针对该算子的 `infiniop-test` 用例能在目标加速卡物理机或沙箱环境中运行通过，包含对 Float32 与 Float16 数据精度的覆盖。
  - 硬件计算结果与参照 CPU 版本的逐元素差值控制在指定平台的数据容差范围内。

**2. 前置依赖、输入输出及接口变动清单**
- **前置依赖**：各目标硬件厂商最新的底层驱动库（如 CUDA Toolkit，特定设备的驱动包）及 `xmake.lua` 中相关的构建描述环境配置。
- **输入输出**：特定平台下硬件指令的直接派发及状态捕获。
- **接口变动清单**：
  - `src/infiniop/ops/xxx/` 目录下的硬件特定分支逻辑（如处理设备特定的内存排布转换逻辑，补充特定后端下的 `operator.cc` 实现细节）。

**3. 测试策略与回归范围**
- **测试策略**：在多平台的 CI/CD 物理机或容器环境中挂载测试，重点检查该硬件对内存对齐（Alignment）要求、块大小（Block size/Thread grid）配置不当引发的静默错误。
- **回归范围**：目标平台的硬件上下文设备切换逻辑、多流（Multi-Stream）同步原语与内存异步搬运稳定性。

**4. 预计工作量与优先级**
- **预计工作量**：3 人日
- **优先级**：中 (P1)
